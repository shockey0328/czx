## 分省看板：26年8月同比新用户缺失 —— 根因诊断
- 现象：`trend-data.js` 中 `26年8月` 各省 `同比新用户` 均为 `null`，而同比活跃/营收/使用率/ARPU 均正常，环比新用户也正常。
- 根因：**不是 build 逻辑 bug，是历史 Excel 缺列**。`build_trend_data.js` 计算同比要求 `lastYear.新用户 != null`；26年8月的去年同月是 25年8月，而 `趋势分析/25年8月.xlsx` 根本没有「新用户」列（表头只有 名称/活跃用户/营收/使用用户/ARPU/使用率），所以 lastYear.新用户 为 null → 同比为 null。
- 逐月盘点「新用户」列缺失情况：
  - 缺失：25年1月、2月、8月、9月、10月、11月、12月、26年1月、2月
  - 有值（34/34 行）：25年3~7月、26年3~8月
- 连带影响：25年8月~26年2月 这 7 个月连**新用户绝对值**都是 null，看板趋势曲线在这段是断的；不只是同比缺失。
- 修复方案：已生成 `分省数据看板（月度）/sql/province_newuser_backfill_202501-202602.sql`，一次查 2025-01~2026-02（覆盖所有缺列月份）的分月分省新用户（首访口径，与原 ② 完全一致），返回 `dt_month/province/new_user_uv`。等用户返回后回填到对应月份 Excel 的「新用户」列，再 `node 趋势分析/build_trend_data.js` 重建 trend-data.js，同比/环比即可全部补齐。
- 注：该 SQL 的 user_logs 是全表扫描（首访口径要求），与原单月新用户 SQL 成本相当，一次查 14 个月不会显著增加开销。
