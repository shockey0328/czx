# 用户行为看板 - 数据状态与操作说明

## 当前数据状态（请以实际为准）

| 项目 | 说明 |
|------|------|
| **date_index** | 当前索引中仅有 2026-02-26 ～ 2026-03-05（9 天） |
| **data/*.json** | 若目录下已有 2026-03-06.json、2026-03-07.json，则索引可能未同步 |
| **待导入** | 2026-03-08 需从「2026年3月8日用户行为日志.xlsx」生成 JSON |

## 推荐操作顺序

### 1. 若 data 下已有 03-06、03-07 的 JSON，但 date_index 里没有

先同步索引（不重新读 Excel）：

```bash
cd 用户行为看板（周度）
node db-manager.js rebuild
```

会把 `data/` 下所有 `YYYY-MM-DD.json` 重新扫一遍，更新 `date_index.json` 和 `user_index.json`。

### 2. 仅导入「尚未有 JSON」的日期（如 3 月 8 日）

在「用户行为看板（周度）」目录下执行：

```bash
node db-manager.js import-new
```

- 会只处理 **date_index 里还没有的日期** 对应的 Excel。
- 若 3 月 8 日等单日 Excel 较大（约 40MB+），建议用 16GB 内存执行：

```bash
node --max-old-space-size=16384 db-manager.js import-new
```

或双击同目录下的 **仅导入新增日期-大内存.bat**（脚本内已带上述参数）。

### 3. 导入完成后验证

导入跑完后，按下面步骤确认是否成功：

| 步骤 | 检查项 | 如何确认 |
|------|--------|----------|
| 1 | 终端输出 | 看到 `导入完成。本次新增 xxx 条记录，当前共 xx 天。` 且无报错 |
| 2 | `data/2026-03-08.json` | 文件存在，且体积合理（与其它单日 JSON 同量级） |
| 3 | `data/indexes/date_index.json` | 打开文件，应包含一行 `"2026-03-08": "E:\\...\\data\\2026-03-08.json"` |
| 4 | 统计一致 | 在项目目录执行 `node db-manager.js stats`，可用日期列表中应出现 `2026-03-08` |

**快速检查命令（PowerShell，在项目根目录）：**

```powershell
# 是否存在 3 月 8 日数据文件
Test-Path ".\用户行为看板（周度）\data\2026-03-08.json"

# 查看当前统计与可用日期
cd ".\用户行为看板（周度）"; node db-manager.js stats
```

若 `date_index.json` 里没有 2026-03-08 但 `data/2026-03-08.json` 已存在，说明索引未更新，执行一次 `node db-manager.js rebuild` 即可修复。

### 4. 上传到 GitHub Release 与 Vercel

- 将新生成的 `data/2026-03-08.json`（以及如需的 03-06、03-07）上传到当前使用的 Release Assets。
- `api/getData.js` 中 `AVAILABLE_DATES` 已包含 03-06、03-07、03-08，无需改代码，推送后 Vercel 会自动部署。

## 常用命令速查

| 命令 | 作用 |
|------|------|
| `node db-manager.js rebuild` | 按 data/*.json 重建索引（索引与现有 JSON 不一致时用） |
| `node db-manager.js import-new` | 仅导入「索引中还没有」的日期对应 Excel |
| `node --max-old-space-size=4096 db-manager.js import-new` | 同上，4GB 内存（大 Excel 用） |
| `node db-manager.js stats` | 查看当前用户数、记录数、可用日期 |

## 若 3 月 8 日导入时一直卡住

- **原因**：3 月 8 日 Excel 较大，默认 Node 内存不足，解析或写入时会很慢甚至像“卡死”。
- **做法**：
  1. 先按 `Ctrl+C` 结束当前导入。
  2. 若只需补 3 月 8 日：双击 **仅导入新增日期-大内存.bat**（或执行 `node --max-old-space-size=16384 db-manager.js import-new`）。
  3. 若是全量重算：双击 **全量导入-大内存.bat**（或执行 `node --max-old-space-size=16384 db-manager.js import`）。
- **进度**：脚本已加日志，会依次出现「读取文件中…」「已读取 x MB，正在解析…」「已解析 x 行…」「正在按用户分组并写入…」「保存 2026-03-08: …」。若停在某一步很久，多半是该步在吃内存，用上面大内存方式再跑即可。
- **若解析超过 5 分钟仍卡住**：可改用 CSV 导入（更快、不卡）。在 Excel 中打开该日期的「用户行为日志.xlsx」→ 另存为 **CSV UTF-8（逗号分隔）**，文件名保持为同一天，如 `2026年3月8日用户行为日志.csv`，放在与 .xlsx 同一目录。再运行「仅导入新增日期-大内存.bat」，脚本会**优先读取同名的 .csv**，流式解析，通常 1～2 分钟内完成。
