# 用户行为看板 - 数据状态与操作说明

## 当前数据状态（请以实际为准）

| 项目 | 说明 |
|------|------|
| **date_index** | 当前索引中仅有 2026-02-26 ～ 2026-03-05（9 天） |
| **data/*.json** | 若目录下已有 2026-03-06.json、2026-03-07.json，则索引可能未同步 |
| **待导入** | 2026-03-08 需从「2026年3月8日用户行为日志.xlsx」生成 JSON |

## 推荐操作顺序

### 1. 若 data 下已有 03-06、03-07 的 JSON，但 date_index 里没有

先同步索引（不重新读 Excel）：

```bash
cd 用户行为看板（周度）
node db-manager.js rebuild
```

会把 `data/` 下所有 `YYYY-MM-DD.json` 重新扫一遍，更新 `date_index.json` 和 `user_index.json`。

### 2. 仅导入「尚未有 JSON」的日期（如 3 月 8 日）

在「用户行为看板（周度）」目录下执行：

```bash
node db-manager.js import-new
```

- 会只处理 **date_index 里还没有的日期** 对应的 Excel。
- 若 3 月 8 日等单日 Excel 较大（约 40MB+），建议用 8GB 内存执行：

```bash
node --max-old-space-size=8192 db-manager.js import-new
```

或双击同目录下的 **仅导入新增日期-大内存.bat**（脚本内已带上述参数）。

### 3. 上传到 GitHub Release 与 Vercel

- 将新生成的 `data/2026-03-08.json`（以及如需的 03-06、03-07）上传到当前使用的 Release Assets。
- `api/getData.js` 中 `AVAILABLE_DATES` 已包含 03-06、03-07、03-08，无需改代码，推送后 Vercel 会自动部署。

## 常用命令速查

| 命令 | 作用 |
|------|------|
| `node db-manager.js rebuild` | 按 data/*.json 重建索引（索引与现有 JSON 不一致时用） |
| `node db-manager.js import-new` | 仅导入「索引中还没有」的日期对应 Excel |
| `node --max-old-space-size=4096 db-manager.js import-new` | 同上，4GB 内存（大 Excel 用） |
| `node db-manager.js stats` | 查看当前用户数、记录数、可用日期 |
