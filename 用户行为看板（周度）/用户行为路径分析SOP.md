# 用户行为路径分析 SOP

> 适用：产品 / 运营 / 教研 / 客服协作，对**已知用户 ID**做路径还原与归因。  
> 工具：用户行为看板（小橙子 AI）。  
> 原则：只依据真实埋点；AI 为辅助；关键结论需人工复核。

---

## 1. 目的

把「翻海量埋点」固化为可重复流程：

1. 拿到用户 ID 与时间范围  
2. 还原真实行为路径（橙子学 / 学伴）  
3. 形成可读结论（卡点、习惯、建议）  
4. 沉淀到工单 / 周报 / 需求讨论

---

## 2. 何时走本 SOP

| 场景 | 典型问题 |
| --- | --- |
| 客诉 / 工单复盘 | 用户说「打不开 / 找不到 / 付不了」，实际卡在哪？ |
| 流失 / 沉默归因 | 最后一次会话停在哪一步？之前有没有未完成动作？ |
| 转化个案 | 浏览 → 预览 → 练习/下载 → 会员/支付是否走完？ |
| 改版 / 活动验证 | 目标路径是否按预期发生？是否出现反复点击、中途退出？ |
| 用户故事沉淀 | 某类用户（如练题型、找卷型）的典型路径是什么？ |

**前置条件**：必须有**数字用户 ID**（可多个，英文逗号分隔）。本流程不能按姓名搜用户。

---

## 3. 角色与输入

| 角色 | 职责 |
| --- | --- |
| 需求提出方 | 提供用户 ID、关注时段、业务问题一句话 |
| 分析执行方 | 按本 SOP 查看板、出结论、标注证据条数 |
| 结论使用方 | 复核后写入工单/周报；决定是否立需求 |

**最小输入清单**

- [ ] 用户 ID（数字；多 ID 用英文逗号）  
- [ ] 起止日期（建议单次 ≤ 7 天；**行为量少的用户可放宽时间窗**，以查全路径为准，不必硬卡 7 天） 
- [ ] 要回答的问题（一句话）  
- [ ] 分析模式：常规全景 / 针对性深挖  
- [ ] **转化节点定义**（本次分析什么算「走完 / 完成」，如支付成功、下载完成、练习提交——未定义时 AI 默认「页面出现即到达」，会虚高转化，务必先给）  
- [ ] **用户分群 / 预期类型**（可选，便于归类结论，如搜索型 / 练习型 / 会员型 / 流失型）

## 4. 标准流程

### Step 0｜打开看板

| 入口 | 地址 |
| --- | --- |
| 本机 / 内网（推荐） | http://localhost:3001/dashboard-db.html 或 http://172.16.32.24:3001/dashboard-db.html |
| 统一门户 | 周度 → **用户行为**（经 `user-behavior.html` 跳转，见 `intranet-user-behavior.json`） |

确认顶部状态含：**数仓就绪**、**DeepSeek 已配置**（或等价成功提示）。若一直转圈 / 失败，先联系服务维护方，勿用编造路径顶替。

### Step 1｜选定日期

1. 默认优先「问题发生日 ±1～2 天」或「客诉反馈日所在周」  
2. 单次建议 **≤ 7 天**；用户极活跃时再缩短，**行为量少的用户可放宽时间窗以查全路径**（不强求 ≤7 天） 
3. 查无数据时：先扩 1～2 天或核对 ID，再反馈维护方  

### Step 2｜填写用户 ID

- 仅数字 ID  
- 多用户对比：`ID1,ID2,ID3`（注意日志量会叠加，日期宜更短）  

### Step 3｜选择分析模式

| 模式 | 何时选 | 预期产出 |
| --- | --- | --- |
| **常规性分析** | 还不清楚问题，要完整故事线 | 轨迹 → 习惯 → 卡点 → 建议（四段） |
| **针对性分析** | 已有明确疑问（流失、支付、学伴等） | 围绕问题：定位 → 原因 → 证据 → 建议 |

### Step 4｜提问并发送

在对话框用**业务语言**描述需求，避免只发「分析一下」。

**路径向（可直接复制）**

- `还原该用户在所选日期内的完整使用路径，按时间说明从哪进入、主要页面顺序、关键点击与退出位置`  
- `对比该用户在橙子学与学伴上的路径，分别说明使用频率与衔接关系`  
- `分析用户从找卷/搜索到预览、练习或下载的路径，指出中断或反复处`  
- `为什么该用户未完成支付/下载？定位最后停留步骤与此前行为`  
- `该用户对学伴的使用路径与使用频率如何？`  

发送后等待约 **30～90 秒**（数仓取数 + AI）。勿重复狂点；超时或报错见文末异常表。

### Step 5｜阅读路径结论（人工复核）

按下面顺序读，并在笔记里勾选：

1. **入口与来源**：从哪进、何端（App/H5 等）  
2. **主路径时间线**：页面/模块顺序是否说得通  
3. **关键动作**：搜索、预览、练习、下载、会员、学伴等是否出现  
4. **中断与反复**：返回、连点、长停、未完成步骤  
5. **退出点**：最后停在哪  
6. **样本**：报告是否注明基于 N 条记录；N 过小则结论降级为「线索」  

**禁止**：把 AI 推测写成已证实事实；禁止补全日志里没有的点击。

### Step 6｜产出与归档

将结论压成可交接的一小段（模板见下），落到：

- 工单备注 / 客服回复依据  
- 周报「个案」小节  
- 需求讨论（卡点 → 是否立项）  

同一问题若换日期复验，注明两次日期与差异。

## 6. 分角色检查点（路径专项）

| 角色 | 路径上必看 |
| --- | --- |
| 产品 | 反馈时段是否对齐；反复点击/流程中断是否可复现为体验问题 |
| 运营 | 进入来源、是否触达活动预期节点、流失停点 |
| 教研 | 找卷 → 预览 → 练习 / 学伴是否顺畅，学科年级是否稳定 |
| 客服协作 | 工单时间线与路径退出点是否一致，便于对外口径 |

---

## 7. 异常速查

| 现象 | 处理 |
| --- | --- |
| 一直转圈 | 确认打开的是 **3001** 服务；Ctrl+F5；如刚改配置，重启服务（「重启服务.bat」） |
| 未找到行为数据 | 核 ID、日期；略扩日期；仍无则反馈维护方 |
| DeepSeek / API 失败 | 稍后重试；缩小日期或用户数；联系维护方查密钥与日志 |
| 结论像「编的」 | 对照「基于 N 条」与业务常识复核；不可用则只保留可核对的时间线事实 |
| 门户跳转失败 | 公司网/VPN；检查 `intranet-user-behavior.json`；本机直开 3001 |
