> 面向 **产品、运营、教研** 的分享与上手文档。

## 一句话说明

这不是一张「看整体指标」的大屏，而是一台 **用户个案放大镜**：已知某个用户 ID 后，还原他在橙子学 / 学伴里做了什么，并用 AI 生成可读的行为解读报告。

| 你想问的问题 | 该用哪个看板 |
| --- | --- |
| 这周整体 UV、留存、营收怎么样？ | **核心数据（周度）** |
| 新增从哪来？渠道结构如何？ | **用户增长（周度）** |
| 用户在搜什么？搜索转化如何？ | **搜索数据（周度）** |
| **这个用户为什么流失 / 卡在哪一步？** | **用户行为（本看板）** |

## 1. 从设计到现在：它解决什么问题

### 设计初衷

橙子学埋点量很大（橙子学 + 学伴），业务同学很难直接翻原始日志。看板的目标是：

1. **按用户 ID + 日期** 快速取出真实行为明细（页面、点击、来源、平台等）
2. 用 **AI（小橙子助手）** 把埋点翻译成产品 / 运营可读的报告
3. 支持两类分析：**常规全景复盘** 与 **针对具体问题的深挖**

### 能力演进（简要）

| 阶段 | 能力 |
| --- | --- |
| 早期 | 读 Excel / CSV 日志，人工筛用户 |
| 数据库版 | 按日分片 + 索引，秒级按用户查询；对话式 UI |
| AI 解读 | DeepSeek 输出四段式报告（轨迹 / 习惯 / 卡点 / 建议） |
| 数仓对接 | 可从数仓按日导出，或本机/内网实时按用户查询 |
| 门户集成 | 统一门户「周度 → 用户行为」可跳转至服务入口 |

**覆盖产品范围**：橙子学（czx）与学伴（xueban）相关埋点，非全站所有产品线。

## 3. 三分钟上手（标准流程）

页面核心区域：**日期** → **用户 ID** → **分析模式** → **描述问题并发送**。

### 步骤

1. **确认数据范围**  
   顶部「总用户数 / 总记录数 / 可用天数」表示当前能查到的数据覆盖。日期请选在可用范围内。
2. **选择起始日期、结束日期**  
   建议一次查 **≤ 7 天**（用户越活跃，日志越多；过长可能分析不全或超时）。
3. **填写用户 ID**  
   - 必须是 **数字 ID**  
   - 多个用户用 **英文逗号** 分隔，如：`77821274,12345678`  
   - 本看板 **不能按姓名搜索用户**，ID 需来自客服工单、后台、其他系统或同事提供
4. **选择分析模式**
   - **常规性分析**：不知道具体问题，想看完整路径与习惯 → 输出四段报告
   - **针对性分析**：已有明确疑问（流失、转化、卡点等）→ 围绕问题深挖
5. **在对话框描述需求，点击发送**（Enter 发送，Shift+Enter 换行）

### 可直接复制的提问示例

**常规性分析：**

- `分析用户的完整使用路径`
- `查看该用户的高频操作习惯`
- `复盘用户在试卷详情与预览上的行为`

**针对性分析：**

- `为什么用户在搜索后就流失了？`
- `用户在哪个环节卡住了？`
- `定位该用户未完成下载/支付的原因`
- `用户为何反复点击某个按钮？`

## 4. 怎么读 AI 报告

### 常规性分析：四段结构

| 模块 | 看什么 | 业务用途 |
| --- | --- | --- |
| **一、用户完整行为轨迹** | 从哪进、访问几次、页面顺序、关键点击、在哪退出 | 还原故事线，对齐客诉/反馈时间点 |
| **二、用户使用习惯与特征** | 高频页面、高频操作、节奏（快/犹豫/反复）、偏好 | 判断用户类型（搜索型、浏览型、练习型等） |
| **三、产品问题与体验卡点（重点）** | 中断、反复点击、长时间无操作、关键步骤未完成 | **优先看**：找体验与转化问题 |
| **四、产品&运营优化建议** | 流程、引导、结构、召回与转化方向 | 形成可讨论的改进点（需结合业务判断） |

报告底部通常会提示「基于 N 条记录」，可据此判断样本是否充足。

### 针对性分析

输出会更贴近你的问题（问题定位 → 原因 → 证据 → 建议），不一定拆成四段。适合周报深挖、工单复盘、转化专项。

### 重要原则（分享时务必说明）

- AI **只应基于真实日志** 描述行为，**不编造**未出现的操作  
- AI 结论是 **辅助解读**，不是最终业务结论；关键决策请对照原始场景与产品逻辑复核  
- 若提示「未找到行为数据」：先核验 **用户 ID** 与 **日期是否在数据范围内**

## 5. 分角色怎么用

### 产品

| 场景 | 怎么用 |
| --- | --- |
| 用户反馈「找不到下载 / 预览打不开」 | 针对性分析：还原反馈时段路径，看是否反复点击、中途退出 |
| 改版后验证 | 对比改版前后同一类用户的路径是否变短、卡点是否减少 |
| 转化漏斗个案 | 看浏览 → 全预览 → 练习 / 下载 → 会员页是否走完 |
| 体验卡点盘点 | 常规分析看「模块三」，汇总多用户共性问题再立需求 |

**建议提问**：`分析用户在试卷详情到下载之间的完整路径，指出可能的体验卡点`

---

### 运营

| 场景 | 怎么用 |
| --- | --- |
| 高价值 / 沉默用户复盘 | 常规分析看习惯与最后活跃行为 |
| 渠道差异 | 关注报告中的进入来源、平台（App / 微信 / H5 等） |
| 流失召回 | 针对性分析最后一次会话停在哪、之前是否有未完成动作 |
| 活动效果个案 | 活动期内用户是否按预期路径完成目标行为 |

**建议提问**：`为什么该用户在活动期间访问后没有完成目标行为？最后停在哪一步？`

---

### 教研

| 场景 | 怎么用 |
| --- | --- |
| 了解「找卷」路径 | 用户如何搜索、浏览详情、全预览、进练习 |
| 学伴使用情况 | 是否进入学伴相关页面（如拍搜等），与试卷场景如何衔接 |
| 内容使用深度 | 是否只扫一眼详情，还是有预览、练习、报告等更深行为 |
| 教研活动复盘 | 活动用户是否真正接触到指定试卷 / 练习环节 |

**注意**：本看板看的是 **产品使用行为**，**不能替代**试卷内容质量、题目对错或教学效果评估。内容本身好坏需结合教研工具与业务数据另看。

**建议提问**：`该用户如何查找和使用试卷？是否有全预览、在线练习或学伴相关行为？`

## 6. 页面上能看到什么

| 区域 | 说明 |
| --- | --- |
| 顶部统计 | 当前数据覆盖的用户数、记录数、可用天数 |
| 日期筛选 | 限定分析时间窗 |
| 用户 ID | 查询主键（可多选） |
| 分析模式 | 常规 / 针对性 |
| 小橙子对话框 | 输入问题、查看 AI 报告 |
| 刷新统计 | 重新拉取当前服务上的数据概览 |

当前版本 **没有** 传统折线/柱状大盘图表，也 **没有** 一键导出报告按钮；需要对外分享时，可复制对话框中的分析文本。

## 7. 使用边界与注意点

1. **必须先有用户 ID** — 看板不做「按昵称 / 手机号」检索。  
2. **日期要在已有数据内** — 超出范围会查不到；以页面顶部可用天数 / 状态提示为准。  
3. **一次查询不宜过长** — 建议 ≤ 7 天；特别活跃用户日志量很大。  
4. **多用户合并分析** — 逗号分隔多个 ID 时，报告是合并视角，个案细节可能被冲淡；深挖建议一次一个用户。  
5. **数据真实性** — 只展示真实埋点派生出的解读；发现乱码、明显异常时请反馈维护同学查源头，不要自行当正确数据使用。  
6. **与汇总看板配合** — 先用核心 / 搜索看板发现问题人群或异常周，再用本看板做个案验证。

## 8. 常见问题

| 现象 | 可能原因 | 建议 |
| --- | --- | --- |
| 打开页面但无法分析 | 服务未启动或网络不通 | 换推荐独立链接；仍不行联系维护 |
| 提示未找到行为数据 | ID 错误，或该日无数据 | 核对 ID；缩短/调整日期 |
| AI 分析失败 | AI 服务密钥或网络异常 | 稍后重试；联系维护 |
| 报告过于笼统 | 用了常规模式且提问太宽 | 改「针对性分析」并写清具体问题 |
| 门户里打不开 | 需内网 / VPN | 改用 Railway 独立链接分享 |

## 9. 分享会可用提纲（约 10 分钟）

1. **定位差异**（1 分钟）：汇总看板 vs 个案行为看板  
2. **打开方式**（1 分钟）：发独立链接，现场打开  
3. **现场演示**（5 分钟）：选日期 → 填一个真实用户 ID → 常规分析 → 再做一个针对性问题  
4. **怎么读报告**（2 分钟）：重点讲「轨迹」和「卡点」两段  
5. **分角色场景**（1 分钟）：产品验卡点、运营看流失、教研看找卷/练习路径  
6. **边界说明**：需已知 ID；AI 辅助不以编造为准；异常反馈维护
