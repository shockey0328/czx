# 查表规则

## 优先级

默认严格按 `常用表 > bi > ads > dwd > dim`：优先使用可直接回答指标的聚合表；只有粒度、字段或明细不足时才下沉。

## 字段与口径

- 先看单表资源中的“关键字段”和“数据粒度”，再判断是否能直接聚合。
- `dt`、`ds` 等分区字段必须出现在查询过滤条件中。
- `cnt`、`num`、`sum`、`amount` 等指标要结合资源中的 ETL 聚合说明确认，不能仅凭字段名推断去重口径。
- 本地解析未提供的字段注释、粒度和指标口径，必须标记为待确认。

## 实时校验

候选表确定后，调用 `mcp__maxcompute__get_table_schema`；需要判断可用分区时再调用 `get_partition_info`。项目映射为：`bi/ads -> dmp_ads`，`dwd/dim -> dmp_cdm`。执行 SQL 统一使用 `dmp_analyst` 提交。

## 输出建议

找表时输出 1-3 张候选表、层级、粒度、关键字段和推荐原因。写 SQL 时注明真实表名、关键字段、分区过滤和指标口径；SQL 上方使用 `/* 推荐原因：... */` 注释。
