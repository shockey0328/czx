# 看板自动更新脚本使用说明

## 文件清单

```
仓库根目录/
├── 周度更新.bat          ← 双击运行，更新3个周度看板
├── 月度更新.bat          ← 双击运行，更新3个月度看板
└── scripts/
    ├── update_weekly.ps1   ← 周度更新核心逻辑
    ├── update_monthly.ps1  ← 月度更新核心逻辑
    └── README.md           ← 本说明文件
```

---

## 环境要求

| 依赖 | 版本要求 | 检查方式 |
|------|---------|---------|
| Windows | 10 / 11 | — |
| PowerShell | 5.1+（系统自带） | `powershell -version` |
| Node.js | v16+（已有 v22.16.0） | `node -v` |
| Git | 任意版本 | `git --version` |

**首次使用前**，确认各看板目录的 node_modules 已安装：

```bat
:: 周度搜索看板（需要 iconv-lite）
cd 搜索数据看板（周度）
npm install

:: 分省数据看板（需要 xlsx）
cd 分省数据看板（月度）
npm install
```

## 使用方法

### 周度更新（每周执行一次）

**操作步骤：**
1. 把本周新的数据 CSV 放到对应目录（见下表）
2. 双击仓库根目录的 `周度更新.bat`
3. 等待窗口显示汇总结果，自动 git push

**数据文件放置位置：**

| 看板 | 你需要更新的文件 | 放置位置 |
|------|---------------|---------|
| 周度核心数据 | 各 `*_utf8.csv` | `核心数据看板（周度）/` |
| 周度搜索数据 | `第N周搜索词.csv` + 其他搜索 CSV | `搜索数据看板（周度）/` |
| 周度用户增长 | 4个 `.normalized.csv` | `用户增长数据看板（周度）/` |

> 搜索词文件命名规则：`第14周搜索词.csv`（脚本自动识别最大周数的文件）

---

### 月度更新（每月执行一次）

**操作步骤：**
1. 把本月新的数据文件放到对应目录（见下表）
2. 双击仓库根目录的 `月度更新.bat`
3. 等待窗口显示汇总结果，自动 git push

**数据文件放置位置：**

| 看板 | 你需要更新的文件 | 放置位置 |
|------|---------------|---------|
| 月度核心数据 | `月度核心数据.csv`、`B端核心数据.csv` | `核心数据看板（月度）/` |
| 各模块渗透率 | `各模块渗透率.csv` | `各模块渗透率看板（月度）/` |
| 分省数据 | `26年X月.xlsx`（新增一个月的文件） | `分省数据看板（月度）/趋势分析/` |

> 分省 Excel 命名规则：`26年4月.xlsx`（脚本自动识别最新月份）

## 如果某个看板失败了

脚本会打印 `❌` 和错误原因，但**不影响其他看板继续更新**。

常见原因：
- `找不到文件`：数据 CSV 还没放进对应目录
- `node 命令失败`：对应目录没有运行 `npm install`
- `git push 失败`：网络问题或 GitHub 认证过期，手动运行 `git push` 即可

- 月度路径配置：`scripts/update_monthly.ps1` 第 15–28 行（`# ── 路径配置` 区域）

## 设置定时自动运行（可选）

### Windows 任务计划程序

**周度脚本（每周一早上 9:00）：**
1. 打开「任务计划程序」（搜索栏输入 `taskschd.msc`）
2. 右键「任务计划程序库」→「创建基本任务」
3. 名称：`橙子学看板-周度更新`
4. 触发器：每周 → 星期一 → 09:00
5. 操作：启动程序 → 程序：`wscript.exe`
6. 参数：`//B "C:\完整路径\周度更新.bat"`（替换为实际路径）

**月度脚本（每月1号早上 9:00）：**
1. 同上，触发器改为：每月 → 1日 → 09:00
2. 名称：`橙子学看板-月度更新`
3. 参数指向 `月度更新.bat`
